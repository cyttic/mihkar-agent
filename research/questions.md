# Our research questions

| | Question | Hypothesis (H1) | Null hypothesis (H0) |
|---|---|---|---|
| RQ1 | Is developers' trust in AI related to how much of its code they check? | Developers who trust AI more check less of its code. | Developers who trust AI more do not check less of its code. |
| RQ2 | Do reviewers report a different number of defects when code is labelled as AI-generated? | Reviewers report more defects when the code is labelled as AI-generated. | The label does not increase the number of defects reported. |
| RQ3 | Is AI-written web code more or less accessible than code written by developers? | AI-written web code has more accessibility violations than developer-written code. | AI-written web code does not have more accessibility violations than developer-written code. |

## Definitions

| | Term | Definition |
|---|---|---|
| RQ1 | Developers | Professional developers in Israel (paid, at least one year of experience) who use AI code assistants. |
| RQ1 | Trust | A score on a trust questionnaire. |
| RQ1 | Check | Reading the code line by line or running tests on it before merging, reported as a percentage of the AI code they receive. |
| RQ2 | Reviewers | Professional developers. |
| RQ2 | Design | All reviewers get the same code. Half of them, chosen at random, see the label; the other half see no label. Reviewers are not told what is being tested. |
| RQ2 | Reported defect | A review comment that points to a bug or a security problem, classified by two raters independently, who do not know which group the comment came from. |
| RQ3 | Web code | Web forms built from the same public specification: one form challenge on the Frontend Mentor website. |
| RQ3 | AI-written forms | Generated by AI code assistants from that specification. |
| RQ3 | Developer-written forms | Solutions to the same challenge that developers published on GitHub before 21 June 2022, the date GitHub Copilot became available to all developers, so they were very likely written without AI. |
| RQ3 | Accessibility | The number of WCAG 2.1 AA violations found by an automated checker, per form. |

## Our constraints

| Area | Constraint |
|---|---|
| Scope | This is a research proposal. We plan the study but do not run it in this course. The constraints below describe the conditions the study would have if it were run. |
| Access | We have no access to any company's internal code, code reviews or developers. We can reach developers through our personal networks, LinkedIn and Israeli developer groups online. We can use public data, such as public GitHub repositories. |
| Participants | We expect about 30 to 60 developers to answer an online questionnaire, and about 20 to 40 developers to take part in a short online task (about 20 minutes each). We cannot pay participants. |
| Time | One semester. About 5 weeks for data collection. |
| Ethics | Any study with human participants needs approval from the university ethics committee. Question 2 does not tell reviewers what is being tested, so it needs a debriefing at the end. |
| Floor 2 | All three questions and hypotheses passed floor 2 on 2026-11-08 (question 3 rechecked after its definition changed). |
| Most important goal | We have not decided. Explain what each strategy gains and pays for each question. |
